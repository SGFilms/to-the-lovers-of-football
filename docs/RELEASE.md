# Запуск бота с боевым магазином ЮKassa

Чек-лист этапа 6. Все шаги здесь делает владелец бота: у разработчика нет доступа к серверу, личному кабинету ЮKassa и @BotFather. Команды выполняются на сервере в папке проекта.

Главный помощник — команда `/check` (только для `ADMIN_IDS`). Она проверяет ключи ЮKassa и показывает, какой магазин подключён, открывает `https://ДОМЕН/health`, показывает, приходят ли уведомления ЮKassa, заполнены ли данные исполнителя в оферте, отвечает ли сайт ЛФЛ и уходят ли копии базы. В конце пишет итог: ❌ есть проблемы, 🧪 подключён тестовый магазин или ✅ бот готов принимать оплаты.

## 1. Подготовка сервера

- [ ] Сервер обновлён до последней версии бота:

  ```bash
  git pull
  docker compose --profile prod up -d --build
  ```

- [ ] Сервер лучше держать в России: сайт ЛФЛ не отвечает на зарубежные адреса, а данные пользователей из России по 152-ФЗ должны храниться в России.
- [ ] Старый бот на Amvera остановлен (или приложение там удалено), если новый работает с тем же токеном. Два бота с одним токеном мешают друг другу: Telegram отдаёт сообщения то одному, то другому, а в логах `docker compose logs bot` появляется `Conflict: terminated by other getUpdates request`.
- [ ] Файл `.env` закрыт от других пользователей сервера: `chmod 600 .env`.
- [ ] Резервные копии: `/backup` присылает файл копии в Telegram (и на почту, если задан `BACKUP_EMAIL`). Если задан `BACKUP_PASSWORD`, пароль записан у вас не только на сервере. Один раз проверьте восстановление на тестовом прогоне: `scripts/restore.sh` с присланным файлом (раздел «Резервные копии» в README).

## 2. Прогон на тестовом магазине

В `.env` на сервере стоят ключи **тестового** магазина (секретный ключ начинается с `test_`). Деньги не списываются. Платить тестовой картой `5555 5555 5555 4444`, срок любой будущий, CVC любой.

В тестовом магазине в «Интеграция» → «HTTP-уведомления» должен быть адрес `https://ДОМЕН/yookassa/webhook` и события `payment.succeeded`, `payment.canceled`, `refund.succeeded`.

| # | Что сделать | Что должно получиться |
|---|---|---|
| 1 | `/check` | ЮKassa: тестовый магазин. Адрес сервера отвечает. Итог 🧪. |
| 2 | Со второго аккаунта Telegram (или попросить знакомого) отправить боту `/start` | Обложка, цена, кнопки «Посмотреть пример», «Оформить подписку», «Помощь». |
| 3 | «Посмотреть пример», написать название команды, например `Монтана` | Расписание команды. Повторный поиск просит оформить подписку. |
| 4 | «Оформить подписку» → «Оплатить» → оплатить тестовой картой | На странице ЮKassa сумма 1 ₽. После оплаты в бот приходит «✅ Оплата получена! Подписка активна до …» (до минуты). |
| 5 | Посмотреть сообщения администратору | Пришло уведомление об оплате: сумма, дата, услуга, Telegram ID, номер платежа. |
| 6 | `/check` | Уведомления ЮKassa: приходят, последнее — время оплаты. Если ⚠️ «ещё не приходили», проверьте адрес уведомлений в магазине: оплата засчиталась фоновой сверкой, а не уведомлением. |
| 7 | «Моя подписка» | Дата окончания через 30 дней, оплата в истории. |
| 8 | Оплатить ещё раз (продление) | Дата окончания сдвинулась ещё на 30 дней, а не от сегодня. |
| 9 | «Оформить подписку», открыть ссылку, не платить, нажать «Я оплатил» | Сообщение, что оплата ещё не пришла. Повторное «Оформить подписку» показывает ту же ссылку. |
| 10 | Личный кабинет тестового магазина → «Платежи» → последний оплаченный → «Вернуть» всю сумму | Пользователю приходит сообщение о возврате, дата окончания уменьшилась на 30 дней, администратору пришло уведомление о возврате. |
| 11 | `/user ID` (ID из уведомления об оплате) | Карточка: подписка, платежи со статусами, включая возврат. |
| 12 | `/payment номер` | Карточка платежа, статус проверен в ЮKassa. |
| 13 | `/grant ID 5`, затем `/grant ID -5` | Пользователю пришло сообщение о 5 днях. Дата вернулась обратно, о снятии сообщения нет. |
| 14 | `/grant ID -N`, чтобы до конца подписки осталось меньше 3 дней, и подождать до 15 минут | Напоминание об окончании подписки с кнопкой «Продлить». |
| 15 | «Помощь» → «Написать отзыв», отправить текст | Отзыв пришёл администраторам. |
| 16 | Открыть в браузере `https://ДОМЕН/offer` и `https://ДОМЕН/privacy` | Оферта и политика открываются, в них стоят ваши данные. |
| 17 | `/stats` | Пользователи, оплаты и возврат посчитаны, ЮKassa: тестовый магазин. |

Если что-то пошло не так, пришлите разработчику номер шага, что произошло и вывод `docker compose logs --tail 200 bot`.

## 3. Перед переключением на боевой магазин

- [ ] В `.env` заполнены `SELLER_NAME` (ФИО), `SELLER_INN` и `SELLER_EMAIL`. С боевым магазином `/check` считает пустые поля проблемой.
- [ ] Оферта и политика (`src/lflbot/legal.py`) проверены вами или юристом. Это черновики.
- [ ] Боевой магазин ЮKassa активирован и принимает платежи. Если ЮKassa просит ссылку на сайт или оферту, дайте `https://ДОМЕН/offer`.
- [ ] Решение по правилам Telegram принято: Telegram требует продавать цифровые услуги за Telegram Stars (подробнее в плане проекта, раздел «Риски»).

## 4. Переключение на боевой магазин

1. В личном кабинете ЮKassa откройте **боевой** магазин:
   - «Интеграция» → «Ключи API»: скопируйте shopId и выпустите секретный ключ (начинается с `live_`).
   - «Интеграция» → «HTTP-уведомления»: адрес `https://ДОМЕН/yookassa/webhook`, события `payment.succeeded`, `payment.canceled`, `refund.succeeded`. Настройки уведомлений у тестового и боевого магазина отдельные.
2. На сервере замените в `.env` значения `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` на боевые. Ключи нигде больше не пишите, в чат тоже.
3. Перезапустите бота, чтобы он прочитал новый `.env`:

   ```bash
   docker compose --profile prod up -d --force-recreate bot
   ```

4. `/check`: ЮKassa — боевой магазин, все строки ✅, кроме «Уведомления ЮKassa: с запуска бота ещё не приходили» (это нормально до первой оплаты).

Неоплаченные ссылки тестового магазина после переключения бот сам считает отменёнными: боевой магазин о них не знает, и при первой сверке (до минуты) бот перестаёт их показывать. Следующее «Оформить подписку» создаст ссылку уже в боевом магазине.

## 5. Настоящая оплата 1 ₽

1. Со своего аккаунта Telegram: «Оформить подписку» → «Оплатить» → оплатить своей картой или через СБП.
2. Должно прийти «✅ Оплата получена!», а администратору — уведомление об оплате.
3. `/check`: итог «✅ Бот готов принимать оплаты», уведомления ЮKassa приходят.
4. Платёж виден в личном кабинете боевого магазина в «Платежи».
5. Пробейте чек в «Мой налог» по данным из уведомления. Дальше так же на каждую оплату; при возврате — аннулируйте чек.
6. По желанию: верните этот 1 ₽ в личном кабинете ЮKassa и проверьте, что бот снял 30 дней. Чек в «Мой налог» тогда тоже аннулируйте.

## 6. Если что-то сломалось

- **Оплата прошла, а подписка не включилась.** `/payment номер` (номер есть в личном кабинете ЮKassa) заново проверит платёж и засчитает его. Если не помогло — `/grant ID 30` и логи разработчику.
- **Вернуться на тестовый магазин.** Верните тестовые ключи в `.env` и выполните команду из шага 4.3.
- **Бот не отвечает.** `docker compose ps` и `docker compose logs --tail 200 bot`. Перезапуск: `docker compose --profile prod up -d`.
- **Старым подписчикам нужен доступ.** Данные старой базы не переносятся: выдайте дни вручную, `/grant ID дни`.
