# To the lovers of football

Telegram-бот для любителей футбола из ЛФЛ: показывает расписание матчей команды по подписке.

Бот работает в Docker: контейнер бота, база PostgreSQL и (на сервере) Caddy, который выдаёт HTTPS-сертификат для уведомлений ЮKassa.

## Запуск на своём компьютере

Нужен [Docker Desktop](https://www.docker.com/products/docker-desktop/) и **тестовый** бот, созданный в @BotFather, чтобы не мешать боевому.

1. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN` (токен тестового бота), `ADMIN_IDS` и `POSTGRES_PASSWORD`. `DOMAIN` оставьте пустым.
2. Запустите в папке проекта:

   ```bash
   docker compose up --build
   ```

3. Напишите тестовому боту `/start`. Остановить бота: `Ctrl+C`.

Данные базы сохраняются между запусками. Чтобы начать с чистой базы: `docker compose down -v`.

## Сервер (Ubuntu)

### Первая установка

1. Направьте домен или поддомен (A-запись) на IP сервера.
2. Установите Docker по [официальной инструкции](https://docs.docker.com/engine/install/ubuntu/).
3. Склонируйте репозиторий и создайте `.env`:

   ```bash
   git clone https://github.com/SGFilms/to-the-lovers-of-football.git
   cd to-the-lovers-of-football
   cp .env.example .env
   nano .env   # токен боевого бота, ADMIN_IDS, POSTGRES_PASSWORD, DOMAIN
   ```

4. Запустите:

   ```bash
   docker compose --profile prod up -d --build
   ```

5. Проверьте, что всё работает: `curl https://ВАШ_ДОМЕН/health` должен вернуть `{"status": "ok"}`.

### Обновление

```bash
git pull
docker compose --profile prod up -d --build
```

Миграции базы применяются автоматически при старте бота.

### Если сервер не достаёт до Telegram

Признак: бот не отвечает, а в `docker compose logs bot` ошибка `TelegramNetworkError: Request timeout error`. Проверка на сервере: `curl -m 10 https://api.telegram.org` зависает и пишет `Connection timed out`. Тогда есть два пути:

1. Попросить поддержку хостинга открыть доступ к `api.telegram.org` (порт 443).
2. Пустить запросы бота к Telegram через прокси-сервер за пределами России. В `.env`:

   ```
   TELEGRAM_PROXY=socks5://хост:порт
   ```

   Допустимы `socks5://логин:пароль@хост:порт`, `socks4://хост:порт` и `http://хост:порт`. Если в пароле есть спецсимволы, запишите их в виде %-кодов (например, `@` как `%40`). Через прокси идут только запросы к Telegram: сайт ЛФЛ, ЮKassa и почта по-прежнему ходят напрямую, как и должны с российского адреса. После правки `.env` перезапустите бота: `docker compose --profile prod up -d --force-recreate bot`. В логах появится строка «Запросы к Telegram идут через прокси».

Адрес прокси содержит пароль: держите его только в `.env`.

### Резервные копии

Бот сам каждый день в 4:00 (по `DISPLAY_TIMEZONE`) делает копию базы и отправляет её за пределы сервера, чтобы база пережила поломку или удаление сервера. Настраивать cron не нужно. Копия — это сжатый файл `lflbot-ГГГГММДД-ЧЧММСС.sql.gz` (с шифрованием `….sql.gz.enc`), обычно от десятков килобайт до нескольких мегабайт. В файле Telegram ID пользователей, сроки подписок и платежи, без имён и карт.

Куда отправлять, задаётся в `.env`:

- **Telegram** (`BACKUP_TELEGRAM=true`, включено по умолчанию). Файл приходит всем `ADMIN_IDS` в чат с ботом. Ничего настраивать не нужно.
- **Почта** (`BACKUP_EMAIL`). Письмо уходит через SMTP-сервер вашего почтового ящика. Для Яндекс Почты:
  1. В [настройках Яндекс ID](https://id.yandex.ru/security/app-passwords) создайте пароль приложения для почты.
  2. В настройках почты → «Почтовые программы» включите доступ по протоколу IMAP (без него Яндекс не принимает письма от программ).
  3. В `.env`:

     ```
     BACKUP_EMAIL=куда-слать@yandex.ru
     SMTP_HOST=smtp.yandex.ru
     SMTP_PORT=465
     SMTP_USER=ваш-ящик@yandex.ru
     SMTP_PASSWORD=пароль приложения
     ```

  Для Mail.ru: `SMTP_HOST=smtp.mail.ru` и пароль для внешних приложений. Некоторые облачные хостинги закрывают исходящую почту (порты 465 и 587) для новых серверов; если `/backup` пишет об ошибке соединения с почтой, попросите поддержку хостинга открыть порт 465.

- **Шифрование** (`BACKUP_PASSWORD`). Если задан, копия шифруется (AES-256), и без пароля её не открыть. Рекомендуется, особенно для Telegram: его серверы находятся за рубежом. Пароль храните отдельно от сервера (например, в менеджере паролей): без него зашифрованную копию не восстановить.

Время копии меняет `BACKUP_TIME` (например `03:30`, пусто — только вручную). Команда `/backup` делает и отправляет копию сразу и пишет, куда она дошла. `/check` показывает, когда была последняя копия и дошла ли. Если ежедневная копия не дошла, бот пишет администраторам.

После изменения `.env` перезапустите бота: `docker compose --profile prod up -d --force-recreate bot`.

**Восстановление.** Скачайте файл копии из Telegram или почты, загрузите его на сервер (например, `scp lflbot-….sql.gz.enc root@IP_СЕРВЕРА:~/to-the-lovers-of-football/`) и выполните в папке проекта:

```bash
scripts/restore.sh lflbot-ГГГГММДД-ЧЧММСС.sql.gz.enc
```

Скрипт спросит пароль шифрования (для `.sql.gz` без шифрования не спросит), проверит, что копия читается, и только после подтверждения заменит текущую базу. На новом сервере сначала выполните «Первую установку», потом восстановление.

**Копии на самом сервере** (по желанию, в дополнение к отправке): `scripts/backup.sh` сохраняет копию в `backups/` и удаляет копии старше 14 дней. Чтобы она делалась каждую ночь, добавьте строку в `crontab -e`:

```
0 4 * * * cd /путь/к/to-the-lovers-of-football && scripts/backup.sh >> backups/backup.log 2>&1
```

## Расписание с сайта ЛФЛ

Бот берёт данные со страниц page.lfl.ru: поиск команды и календарь её матчей. Данные читаются из JSON, который сайт кладёт в страницу (блок `__NEXT_DATA__`), а не из вёрстки.

- Ответы сайта кэшируются на 15 минут. Если сайт не отвечает, бот до 6 часов показывает последнее полученное расписание.
- Запросы идут не чаще одного раза в 3 секунды. Если сайт оборвал соединение, бот 5 минут к нему не обращается: при частых запросах сайт временно перестаёт отвечать.
- Расписания избранных команд подписчиков бот обновляет заранее, в фоне: раз в минуту одну команду (`LFL_WARMUP_INTERVAL`, 0 — выключить), каждую не чаще раза в час. Такое расписание бот отдаёт из памяти до 3 часов, не обращаясь к сайту, поэтому подписчик видит свою команду мгновенно даже при большой нагрузке. Избранная команда — та, которую пользователь смотрел последней; сразу после оплаты бот просит написать название своей команды, если её ещё нет.
- Время матчей сайт отдаёт в UTC, бот показывает его по Москве. Полночь по Москве означает, что время ещё не назначено, и бот пишет «время уточняется».

Проверить вручную: напишите боту название команды, например `Монтана`, или `/schedule Монтана`.

Тесты разбирают сохранённые страницы сайта из `tests/fixtures/lfl`. Если сайт изменится и тесты на новых страницах упадут, замените файлы там свежими копиями.

## Как бот выглядит для пользователя

Бот работает только в личной переписке и показывает всё в одном сообщении-экране: кнопки редактируют его, а не присылают новые.

- **/start без подписки** — обложка, что умеет бот, цена и кнопки «Посмотреть пример», «Оформить подписку», «Помощь».
- **/start с подпиской** — главное меню: «Расписание», «Моя подписка», «Помощь» и строка «Подписка активна до…». Последняя команда, которую смотрел пользователь, появляется в меню отдельной кнопкой «⭐ Название».
- **Расписание** — любое сообщение в чате считается названием команды. Если команд несколько, бот предлагает выбрать по лиге.
- **Бесплатный пример** — без подписки один раз можно посмотреть расписание. Пример не тратится, если сайт ЛФЛ не ответил или у команды нет матчей.
- **Моя подписка** — статус, дата окончания, последние оплаты, кнопка продления.
- **Помощь** — как пользоваться, «Написать отзыв» (сообщение пересылается всем из `ADMIN_IDS`), оферта и политика конфиденциальности.

При каждом запуске бот обновляет список команд и описание в профиле. Аватар ставится, только если у бота его ещё нет, поэтому свой аватар, загруженный в @BotFather, бот не трогает.

Картинки лежат в `src/lflbot/assets`: `cover.png` (обложка приветствия, 1280×640) и `avatar.png` (аватар, 640×640). Чтобы поставить свои, замените файлы с теми же именами.

### Оферта и политика конфиденциальности

Тексты лежат в `src/lflbot/legal.py`. Это черновики: проверьте их сами или с юристом до запуска с боевым магазином. Данные исполнителя берутся из `.env`: `SELLER_NAME` (ФИО), `SELLER_INN`, `SELLER_EMAIL`. Пока они пустые, в тексте стоит «не указано».

Оферта и политика открываются в боте из «Помощи». На сервере они ещё и доступны по адресам `https://ВАШ_ДОМЕН/offer` и `https://ВАШ_ДОМЕН/privacy`: эти ссылки можно указать в настройках магазина ЮKassa.

## Подписка и оплата

Подписка стоит 1 ₽ за 30 дней (меняется переменными `SUBSCRIPTION_PRICE` и `SUBSCRIPTION_DAYS`). Пользователь нажимает «Оформить подписку» (или пишет `/subscribe`), получает кнопку «Оплатить», платит на странице ЮKassa и возвращается в бот. `/subscription` показывает дату окончания и историю оплат.

- Каждая оплата добавляет 30 дней к текущей дате окончания, а если подписки нет или она закончилась, к текущему моменту.
- Одна оплата засчитывается ровно один раз, сколько бы раз бот её ни проверял.
- Пока у пользователя есть неоплаченная ссылка моложе 50 минут, бот показывает её же, а не создаёт новый платёж.
- Полный возврат денег в личном кабинете ЮKassa снимает 30 дней этой оплаты.
- Напоминания приходят за 3 дня, меньше чем за сутки и когда подписка закончилась, каждое один раз.

### Как бот узнаёт об оплате

Статус платежа бот всегда перепроверяет через API ЮKassa. Поводов перепроверить три:

1. Уведомление ЮKassa на `https://ВАШ_ДОМЕН/yookassa/webhook` (только на сервере). Бот принимает уведомления только с адресов ЮKassa.
2. Фоновая сверка неоплаченных платежей раз в минуту (`PAYMENT_CHECK_INTERVAL`). Благодаря ей оплата работает и на вашем компьютере без домена.
3. Кнопка «Я оплатил» под ссылкой на оплату.

### Настройка ЮKassa

1. В личном кабинете ЮKassa откройте тестовый магазин, раздел «Интеграция» → «Ключи API». Впишите в `.env` `YOOKASSA_SHOP_ID` (shopId) и `YOOKASSA_SECRET_KEY` (секретный ключ). Без них бот работает, но на `/subscribe` отвечает, что оплата пока не подключена.
2. Только для сервера: «Интеграция» → «HTTP-уведомления». Адрес `https://ВАШ_ДОМЕН/yookassa/webhook`, события `payment.succeeded`, `payment.canceled`, `refund.succeeded`.
3. Перезапустите бота.

В тестовом магазине деньги не списываются. Платите [тестовой картой ЮKassa](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing#test-bank-card), например `5555 5555 5555 4444` (без 3-D Secure), срок действия любой будущий, CVC любой.

### Чеки в «Мой налог»

ЮKassa не оформляет чеки самозанятых, поэтому чек пробивается вручную. О каждой оплате бот пишет всем из `ADMIN_IDS`: сумму, дату и время, название услуги, Telegram ID покупателя и номер платежа ЮKassa. О возврате бот тоже пишет, чтобы вы аннулировали чек. Все платежи также видны в личном кабинете ЮKassa в разделе «Платежи».

## Админка и наблюдение

Служебные команды работают только у Telegram ID из `ADMIN_IDS`. Остальным бот отвечает на них, как на неизвестную команду, и в меню команд они видны только администраторам (меню обновляется при запуске бота, если администратор хоть раз писал боту).

- `/admin` — список команд.
- `/stats` — пользователи (всего, новые за сутки и за 7 дней), активные подписки, бесплатные примеры, оплаты и возвраты, неоплаченные ссылки. Внизу состояние: отвечает ли сайт ЛФЛ, какой магазин ЮKassa подключён (тестовый или боевой) и когда бот запущен.
- `/user ID` — карточка пользователя: когда пришёл, подписка, бесплатный пример, избранная команда, последние платежи и выданные вручную дни.
- `/grant ID дни` — добавить дни подписки без оплаты, например `/grant 123456 30`. Дни добавляются после уже оплаченных, пользователь получает сообщение. Выдать можно и тому, кто ещё не писал новому боту.
- `/grant ID -дни` — снять дни, например `/grant 123456 -5`, если выдали лишнее. Пользователю об этом не пишется. За раз не больше 366 дней.
- `/payment номер` — платёж ЮKassa из базы бота. Команда заново проверяет статус в ЮKassa: если оплата прошла, а бот её почему-то не засчитал, она засчитается сейчас.
- `/check` — готов ли бот принимать оплаты: подходят ли ключи ЮKassa и какой магазин подключён (тестовый или боевой), открывается ли `https://ДОМЕН/health`, приходят ли уведомления ЮKassa, заполнены ли данные исполнителя в оферте, отвечает ли сайт ЛФЛ.

Telegram ID пользователя есть в уведомлениях об оплатах и отзывах. Каждая ручная выдача дней сохраняется в базе (кто, кому, сколько и когда).

### Сообщения о сбоях

Бот сам пишет всем из `ADMIN_IDS`, если:

- сайт ЛФЛ не отвечает или изменился так, что бот не может разобрать страницу. Когда сайт снова отвечает, приходит сообщение об этом;
- в обработке сообщения пользователя произошла ошибка;
- не удалась фоновая задача: сверка платежей (например, ЮKassa не отвечает ни на один запрос) или напоминания.

Об одном и том же сбое бот пишет не чаще раза в час и в следующем сообщении указывает, сколько раз он повторился. Подробности ошибок в логах: `docker compose logs -f bot`.

## Что хранит бот

Только числовой Telegram ID пользователя, даты подписки и бесплатного примера, последнюю команду, которую он смотрел, платежи ЮKassa (номер, сумма, статус, даты) и дни, выданные администратором вручную. Имён, ников, телефонов и email бот не хранит. Отзывы пересылаются администраторам и в базе не сохраняются.
